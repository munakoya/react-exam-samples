# 6. 実装時の考え方とつまずき

> [目次](README.md) ｜ 前：[5. 実装手順](05-implementation.md)

## 6-1. 試験の進め方

### 最初の 10 分：作る前に決める

1. 要件を**チェックリストに書き写す**（必須と発展を分ける）。README に貼ると提出物にもなる
2. 画面・データの型・操作を書き出す（[2-1](02-design.md#2-1-要件から画面データ操作を書き出す)）
3. 「保存する値」と「計算する値」を分ける（期限切れ・件数は計算）
4. 実装の順番を決める：**表示 → 追加 → 詳細・編集 → 削除 → 業務の操作（貸出）→ 絞り込み → 見た目**

### 進め方の原則

| 原則                                       | 理由                                                                           |
| ------------------------------------------ | ------------------------------------------------------------------------------ |
| 動く最小のものから作る                     | 見た目が整っていても、追加できなければ評価されない                             |
| 1 機能ずつ作り、動かしてからコミット       | 途中で壊れても、直前のコミットに戻れる。履歴が「考えて作った順番」の証拠になる |
| 必須をすべて終えてから発展へ               | 発展が 1 つできても、必須が 1 つ欠けている方が評価は下がりやすい               |
| MUI の初期の見た目のまま機能を作る         | theme・sx の調整は時間が溶けやすい。最後にまとめて整える                       |
| 部品の使い方は覚えず、カタログからコピー   | [MUI 部品カタログ](../../mui-catalog/) の見本をコピーして直す方が速く、間違いが少ない |
| 詰まったら 15 分で区切る                   | 別の機能を先に進め、あとで戻る                                                 |

### 時間配分の例（3 時間の場合）

ステップごとのチェックリスト付きの手順は [試験の実装手順（雛形から提出まで）](../../starter-mui/docs/README.md)。

| 時間       | やること                                                       |
| ---------- | -------------------------------------------------------------- |
| 0:00〜0:15 | 要件の書き出し・設計                                           |
| 0:15〜0:30 | 環境構築（[1 章](01-setup.md)。[雛形](../../starter-mui/README.md)なら 5 分） |
| 0:30〜2:10 | 必須機能（[5 章](05-implementation.md) のステップ 2〜7）       |
| 2:10〜2:40 | 発展機能（絞り込み・ダッシュボードなど）                       |
| 2:40〜2:50 | 0 件・見つからない の表示、スマホ幅、見た目                    |
| 2:50〜3:00 | 提出前のチェック（[6-5](#6-5-提出前のチェックリスト)）、README |

## 6-2. 迷ったときの判断基準

### これは state にする？

| 質問                               | 答え                                    |
| ---------------------------------- | --------------------------------------- |
| ほかの値から計算できる？           | できるなら state にしない。毎回計算する |
| 日付が変わるだけで変わる？         | 保存しない。今日の日付と比べて計算する  |
| URL を共有・「戻る」でも残したい？ | URL（`useSearchParams`）                |
| そのコンポーネントの中だけで使う？ | `useState`                              |
| 離れた場所・別のページでも使う？   | Zustand の store                        |
| 閉じても残す？                     | persist した store                      |
| フォームの入力値？                 | React Hook Form                         |

### ページにする？ダイアログにする？

| 入力・表示                                         | 選ぶもの    |
| -------------------------------------------------- | ----------- |
| 項目が多い・URL を共有したい・戻るボタンで戻りたい | ページ      |
| 項目が 1〜3 個・一覧を見ながら操作したい           | Dialog      |
| 「本当に？」の確認だけ                             | ConfirmDialog |
| 操作の結果を伝えるだけ                             | 通知（Snackbar・`notify()`） |
| ずっと出しておく注意（期限切れなど）               | Alert       |

### どの層に置く？

| 迷っているもの                                  | 置き場所                |
| ----------------------------------------------- | ----------------------- |
| 判定の関数（期限切れか、貸出中か）              | `entities/<もの>/model` |
| 操作のない表示（状態のラベル・履歴の表）        | `entities/<もの>/ui`    |
| ボタン ＋ ダイアログ、フォーム                  | `features/<操作>`       |
| 2 つの store を同時に動かす処理                 | `features/<操作>`       |
| 複数の entities・features を並べた表            | `widgets`               |
| 1 画面でしか使わない小さな表示                  | その `pages/<画面>/ui`  |
| 日付の計算・通知など、業務に関係ないもの        | `shared`                |

迷ったら「下の層に置けるか」を考える。下に置けるもの（ほかの層を知らなくても書けるもの）ほど使い回しやすい。

### 名前の付け方

| もの                   | 付け方                  | 例                                          |
| ---------------------- | ----------------------- | ------------------------------------------- |
| コンポーネント         | 名詞・大文字始まり      | `BookTable`・`LendBookButton`               |
| 関数・action           | 動詞から                | `addLoan`・`filterBooks`・`getAvailability` |
| 真偽値                 | `is`・`has`・`can` など | `isActiveLoan`・`isFiltering`               |
| store のフック         | `use〇〇Store`          | `useBookStore`                              |
| イベントを受ける props | `on〇〇`                | `onSortChange`・`onDeleted`                 |
| 選択肢の配列・表示名   | 複数形・`〇〇Labels`    | `bookGenres`・`bookGenreLabels`             |

## 6-3. よくあるバグと直し方

### React・Zustand・React Router

| 症状                                                     | 原因                                                           | 直し方                                                                                       |
| -------------------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 画面が固まる・「Maximum update depth exceeded」          | Zustand のセレクターで `filter`・`map`・`{…}` を返している     | 元の値を選んでから計算する（[4-3](04-libraries.md#4-3-zustand)）                             |
| store を変えたのに画面が変わらない                       | 元の配列・オブジェクトを書き換えている（`push`・`x.a = …`）    | スプレッド構文で新しく作る                                                                   |
| 並び替えたら、元の一覧の順番まで変わった                 | `sort()` が store の配列を書き換えた                           | `toSorted()`                                                                                 |
| リンクを押すとページ全体が読み込み直される・state が消える | MUI の Button・Link に `href` を書いた                        | `component={RouterLink} to="…"`                                                              |
| メニューの「本の一覧」が、登録ページでも選択中になる     | NavLink は前方一致で active になる                             | `end` を付ける                                                                               |
| 「今日」が 1 日ずれる                                    | `toISOString()` は UTC                                         | 地域の日付で作る（`todayString()`）                                                          |
| 型を変えたら画面が真っ白・データが消えた                 | localStorage に古い形のデータが残っている                      | DevTools → Application → Local Storage で消す                                                |
| フックのエラー（Rendered more hooks than…）              | `if (!book) return` の後でフックを呼んでいる                   | フックはコンポーネントの一番上にまとめる                                                     |

### React Hook Form ＋ MUI

| 症状                                                     | 原因                                                           | 直し方                                                                                       |
| -------------------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| TextField に入力しても値が入らない・エラーが出ない       | `register` を MUI の部品に渡している／`error` を渡していない   | `Controller`（`FormTextField`）でつなぎ、`error`・`helperText` を渡す                        |
| エラーの入力欄にフォーカスが移らない                     | `field.ref` を TextField の外枠に渡している                    | `inputRef={field.ref}`                                                                       |
| 「A component is changing an uncontrolled input to be controlled」 | `defaultValues` に項目がない（undefined）           | `defaultValues` にすべての項目を書く（未入力は `""`）                                        |
| 「You have provided an out-of-range value」（Select）    | value が MenuItem のどれにも一致しない                         | 未選択は `""` にし、選択肢は配列から作る                                                     |
| 送信ボタンを押しても何も起きない                         | `type="submit"` がない／`<form>` の外にある                    | `type="submit"`。ダイアログでは `<form>` で DialogContent・DialogActions を包む              |
| 数値の項目に `"3"` の文字列が届く                        | 入力欄の値は `type="number"` でも文字列                        | zod で文字列のまま受け取り `.transform(Number)`                                              |
| 編集フォームに前の本の値が出る                           | `defaultValues` は最初の 1 回だけ使われる                      | `key={book.id}` で作り直す                                                                   |
| Rating・Autocomplete の値がフォームに入らない            | `onChange` の第 2 引数が値（event ではない）                   | `onChange={(_e, v) => field.onChange(v)}`                                                    |
| 日付の入力欄でラベルと「年/月/日」が重なる               | 値がないとラベルが中に下りる                                   | `slotProps={{ inputLabel: { shrink: true } }}`                                               |

### MUI v9

| 症状                                                     | 原因                                                           | 直し方                                                                                       |
| -------------------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `InputProps`・`inputProps` で型エラー・効かない          | v9 で削除された                                                | `slotProps={{ input: … }}`・`slotProps={{ htmlInput: … }}`                                   |
| `<Grid item xs={6}>` が効かない                          | v9 の Grid は `size`                                           | `<Grid size={6}>`・`<Grid size={{ xs: 12, md: 6 }}>`                                         |
| `<Stack alignItems="center">`・`<Box mt={2}>` が効かない | v9 でシステム props が削除された                               | `sx={{ alignItems: "center" }}`・`sx={{ mt: 2 }}`                                            |
| `Cannot find module '@mui/icons-material/DeleteOutline'` | v9 で `…Outline` のアイコンが削除された                        | `DeleteOutlined`（`…Outlined`）                                                              |
| 表のページ送りで 1 ページずれる                          | `TablePagination` の page は 0 から                            | `page={page - 1}`・`onPageChange={(_e, p) => setPage(p + 1)}`                                |
| Tooltip が出ない・警告が出る                             | disabled のボタンを直接包んでいる                              | `<Tooltip><span><Button disabled /></span></Tooltip>`                                        |
| 「<li> cannot be a descendant of <li>」                  | ListSubheader・ListItem（どちらも `<li>`）を入れ子にした       | `<ul>`（List）の直下に横に並べる                                                             |
| ダイアログを開くと後ろの表が少し動く                     | スクロールバーが消えて幅が変わる                               | 列に `whiteSpace: "nowrap"` を付けて折り返しを防ぐ                                           |

## 6-4. 動かないときの調べ方

1. **ブラウザのコンソール**（F12 → Console）：赤いエラーの 1 行目と、ファイル名・行番号を見る。MUI の警告（`MUI: …`）も読む
2. **`npm run build`**：型のエラーをまとめて出せる。`npm run dev` は型エラーがあっても動いてしまう
3. **値を出してみる**：`console.log(filter)`。直したら消す
4. **localStorage**：DevTools → Application → Local Storage で、保存された中身を見る・消す
5. **zod のエラー**：`schema.safeParse(value)` の `error` を `console.log` すると、どの項目が合わないか分かる
6. **最小にする**：怪しい部分をコメントアウトして、どこから壊れるかを絞る。直前のコミットとの差分（`git diff`）も見る
7. **MUI の型エラー**：部品の型定義（`node_modules/@mui/material/<部品>/<部品>.d.ts`）に、使える props と初期値（`@default`）が書いてある

## 6-5. 提出前のチェックリスト

### 機能

- [ ] 要件のチェックリストがすべて埋まっている
- [ ] 登録・編集・削除・貸出・返却のあと、**再読み込みしても**残っている
- [ ] 0 件のとき・条件に合うものがないとき・見つからないとき（存在しない URL）の表示がある
- [ ] 入力エラーで止まり、正しく直せば送信できる
- [ ] 削除の前に確認が出る。押せないボタンには理由が出る
- [ ] 日付の境目（今日が期限の貸出）で「期限切れ」にならない

### 見た目・使いやすさ

- [ ] スマホ幅（375px ほど）で崩れない・ページ全体が横にはみ出さない（表は表の中だけでスクロール）
- [ ] アイコンだけのボタンに `aria-label` がある
- [ ] キーボード（Tab・Enter・Esc）でも操作できる（ダイアログは Esc で閉じる）

### コード

- [ ] `npm run build` と `npm run lint` がエラーなしで通る
- [ ] コンソールにエラー・警告が出ていない（MUI の警告も）
- [ ] `console.log` や仮のデータを消した
- [ ] 使っていない import・ファイルがない

### 提出物

- [ ] コミットが機能ごとに分かれている
- [ ] README に「動かし方」「できること」「工夫した点・できなかった点」を書いた
- [ ] `node_modules`・`dist` をコミットしていない

### README に書くとよいこと

```md
## 動かし方

npm install
npm run dev

## できること

- 本の登録・編集・削除、貸出・返却
- …

## 工夫した点

- 「貸出中・期限切れ」は保存せず、貸出の記録と今日の日付から計算している（日付が変わっても正しく表示されるため）
- 本と貸出を別の store にし、両方を動かす処理（削除時に貸出の記録も消す）は features にまとめた
- 検索・絞り込みの条件を URL に持たせ、詳細から戻っても同じ表示になるようにした

## できなかった点・次にやりたいこと

- 予約（貸出中の本の順番待ち）
```

「工夫した点」は**なぜそうしたか**まで書くと、考えて作ったことが伝わる。
