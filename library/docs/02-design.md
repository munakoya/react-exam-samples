## 2-1. 要件から「画面・データ・操作」を書き出す

お題の文章から、名詞と動詞を拾う。

> 図書コーナーの**本**を管理する。本を**登録**し、**誰に貸し出しているか**・**返却期限を過ぎていないか**がひと目で分かる。

- 名詞：本・借りる人・返却期限・状態（貸出中・期限切れ）
- 動詞：登録する・編集する・削除する・貸し出す・返却する・探す

### 画面（URL）

| 画面           | URL                   | 載せるもの                                       |
| -------------- | --------------------- | ------------------------------------------------ |
| ダッシュボード | `/`                   | 集計・期限切れ・期限が近い・最近登録した本       |
| 本の一覧       | `/books`              | 検索・絞り込み・並び替え・表・ページ送り         |
| 本の登録・編集 | `/books/new`・`/edit` | フォーム                                         |
| 本の詳細       | `/books/:bookId`      | 本の情報・今の貸出・貸出の履歴、貸出・返却・削除 |
| 貸出一覧       | `/loans`              | タブ（貸出中・期限切れ・返却済み）と表           |

本の登録・編集は**ページ**にした（項目が多い・URL で開けると便利）。貸出は項目が 2 つだけなので、一覧や詳細の上に出す**ダイアログ**にした。

| 入力の量・使い方                                  | 選ぶもの        |
| ------------------------------------------------- | --------------- |
| 項目が多い・URL を共有したい・戻るボタンで戻りたい | ページ          |
| 項目が少ない・一覧を見ながら操作したい            | ダイアログ      |
| 「本当に？」の確認だけ                            | ConfirmDialog   |

### データ（型）

**本と貸出を別のデータにする**のがこのお題のいちばん大事な判断。

```ts
type Book = {
  id: string;
  title: string;
  author: string;
  genre: "novel" | "business" | "tech" | "design" | "hobby" | "other";
  isbn: string; // 任意。未入力は ""
  publishedYear: number | null; // 任意。未入力は null（数値なので "" にできない）
  rating: number; // 0〜5。0 は「未評価」
  tags: string[];
  memo: string;
  createdAt: string; // "2026-10-05T09:00:00.000Z"
  updatedAt: string;
};

type Loan = {
  id: string;
  bookId: string; // どの本か（本のデータはコピーしない）
  borrower: string; // 借りた人
  loanedAt: string; // 貸出日 "2026-10-05"
  dueDate: string; // 返却期限 "2026-10-19"
  returnedAt: string; // 返却日。まだなら ""
};
```

決め方のポイント：

| 決めたこと                                           | 理由                                                                                                        |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 本に「貸出中か」を持たせず、貸出を別のデータにする   | 1 冊の本は何度も貸し出される。履歴を残すには「貸出 1 回 = 1 件」のデータが要る                              |
| 「貸出中・期限切れ」は保存せず、毎回計算する         | 期限切れは**日付が変わるだけで**変わる。保存すると、毎日書き換える処理が要る                                |
| 貸出には `bookId` だけを持たせる                     | 本のタイトルを直したとき、貸出側を直さなくてよい。表示するときに `bookId` で本を探す                        |
| 返却しても貸出のデータを消さず、`returnedAt` を入れる | 履歴として見せられる。「今の貸出」は `returnedAt === ""` のもの                                             |
| 日付は `"YYYY-MM-DD"` の文字列                       | localStorage（JSON）に `Date` は保存できない。この形は文字列のまま大小比較できる（`dueDate < today`）       |
| 任意の文字列は `""`、任意の数値は `null`             | 入力欄の空は `""`。数値の項目に `""` は入れられないので `null` で「なし」を表す                             |
| 選択肢は英語の値 ＋ 日本語の表示名                   | 表示名を変えても保存データに影響しない。型で打ち間違いに気付ける                                            |

### 操作

| 操作                       | どこから                     | 動かす store |
| -------------------------- | ---------------------------- | ------------ |
| 登録・編集                 | 登録・編集ページ             | 本           |
| 削除（確認つき）           | 一覧の行・詳細               | 本 ＋ 貸出   |
| 貸し出す（ダイアログ）     | 一覧の行・詳細               | 貸出         |
| 返却する（確認つき）       | 一覧の行・詳細・貸出一覧     | 貸出         |
| 検索・絞り込み・並び替え   | 一覧の上・表の見出し         | （URL）      |

この表が、そのまま [5. 実装手順](05-implementation.md) の順番と features のフォルダになる。

## 2-2. 状態をどこに置くか

「状態」とは、変わる値のこと。**置き場所を間違えるのが、いちばん多い設計ミス**。次の順に考える。

```text
その値は、ほかの値から計算できる？ ──はい→ 状態にしない（毎回計算する）
        │いいえ
        ▼
URL を共有・再読み込み・「戻る」をしても残したい？ ──はい→ URL（?q=…&page=2）
        │いいえ
        ▼
アプリを閉じても残したい？ ──はい→ persist した Zustand の store
        │いいえ
        ▼
離れた複数のコンポーネント・ページで同じ値を使う？ ──はい→ Zustand の store
        │いいえ
        ▼
そのコンポーネントの中だけ ──→ useState（フォームなら React Hook Form）
```

このアプリでの判断：

| 値                                       | 置き場所                         | 理由                                                         |
| ---------------------------------------- | -------------------------------- | ------------------------------------------------------------ |
| 本の一覧・貸出の記録                     | Zustand（persist）               | 全ページで使い、閉じても残す                                 |
| 貸出中・期限切れ・件数・今月の貸出数     | **計算**                         | 本・貸出・今日の日付から求められる                           |
| 表示する本（絞り込み・並び替え・ページ） | **計算**                         | 本と条件から求められる                                       |
| 検索・絞り込み・並び順・ページ           | **URL**（`?q=…&sort=…&page=…`）  | 詳細から「戻る」で帰ってきても残る。URL を共有すると同じ表示 |
| 貸出一覧のタブ                           | **URL**（`?tab=overdue`）        | ダッシュボードの「期限切れ」から直接開けるように             |
| 通知（スナックバー）の文言               | Zustand（保存しない）            | どの画面・どの関数からでも出したい                           |
| ダイアログの開閉                         | `useState`                       | そのボタンの中だけで使う                                     |
| フォームの入力値・エラー                 | React Hook Form                  | フォームの中だけで使う                                       |

> **計算できる値は保存しない**。保存すると「元の値」と「計算した値」の 2 か所を同時に直す必要が出て、片方を忘れたときに表示がずれる。期限切れのように「日付が変わるだけで変わる」値は特に。

### URL に持つか、store に持つか

絞り込みの条件は、[タスク管理](../../task-manager/) では store（persist）、このアプリでは URL に持っている。どちらも正解で、**何を残したいか**で選ぶ。

| 置き場所       | 残る場面                                   | 向いている値                           |
| -------------- | ------------------------------------------ | -------------------------------------- |
| URL            | 再読み込み・「戻る」・URL の共有・ブックマーク | 検索・絞り込み・ページ・タブ           |
| store（persist） | アプリを閉じて開き直しても                 | 「いつもこの並び順で見たい」という好み |

## 2-3. なぜ Zustand を使うのか

`useState` は、そのコンポーネント（と props で渡した子）でしか使えない。本の一覧はダッシュボード・一覧・詳細・フォーム（タグの候補）で使うので、**コンポーネントの外に置く場所**が必要になる。

| 方法                             | 向いている場面               | 選ばなかった理由                                             |
| -------------------------------- | ---------------------------- | ------------------------------------------------------------ |
| 親に state を置いて props で渡す | 親子など近い場所             | ページをまたぐと、App まで持ち上げて全ページに配ることになる |
| Context ＋ useReducer            | ライブラリを足したくないとき | Provider で包む・値が変わると中の全員が再描画される          |
| **Zustand**                      | 離れた場所で同じ値を使う     | Provider 不要。使う値だけを選べる。persist で保存もできる    |

store は「値」と「値の変え方（action）」をまとめたもの。画面は `addLoan(input)` を呼ぶだけで、配列をどう変えるかは知らなくてよい。

**本と貸出は別々の store にする**（localStorage のキーも別）。1 つの store にまとめると、貸出を 1 件足すだけで本を表示している画面まで再描画される。entities のフォルダも分かれるので、置き場所も分かりやすい。

## 2-4. なぜ FSD でフォルダを分けるのか

FSD（Feature-Sliced Design）は「何を・どこに置くか」のルール。ルールがあると、

- ファイルを探すとき、置くときに迷わない
- 「どこから使われているか」が層で分かるので、直すときの影響範囲が読める
- 採点者・チームの人が、初めて見ても構成を理解しやすい

### 層と、このアプリのファイル

上の層は下の層を使ってよいが、**下の層から上の層は使わない**（`entities` は `features` を知らない）。

| 層         | 役割                             | このアプリの例                                                                                 |
| ---------- | -------------------------------- | ---------------------------------------------------------------------------------------------- |
| `app`      | アプリ全体の設定                 | ルーティング、テーマ、Provider、全体の枠（RootLayout）                                         |
| `pages`    | URL 1 つ分の画面。組み立てるだけ | `dashboard`・`book-list`・`book-detail`・`book-new`・`book-edit`・`loan-list`                  |
| `widgets`  | entities ＋ features の大きな UI | `book-table`（本の表 ＋ 貸出・返却・削除のボタン）、`loan-table`                               |
| `features` | ユーザーの操作 1 つ              | `book-form`・`lend-book`・`return-book`・`delete-book`・`book-filter`                          |
| `entities` | 扱う「もの」                     | `book`（型・store・アイコン）、`loan`（型・store・状態の判定・状態のラベル・履歴の表）         |
| `shared`   | 業務に関係ない共通のもの         | `ui`（自作部品）、`lib`（日付）、`config`（localStorage のキー）                               |

### 迷ったときの決め方

| これは…                                               | 置き場所                              |
| ----------------------------------------------------- | ------------------------------------- |
| 本の型・store、「期限切れか」のような判定             | `entities/<もの>/model`               |
| 本・貸出の見せ方（操作ボタンなし）：状態のラベルなど  | `entities/<もの>/ui`                  |
| 2 つの store を同時に動かす操作（削除で貸出も消す）   | `features/<操作>`                     |
| 本と貸出の両方を表示する表                            | `widgets`                             |
| URL 1 つ分の画面                                      | `pages`                               |
| 本に関係なく、どのアプリでも使えるもの（日付・通知）  | `shared`                              |

### 守ること

1. **同じ層の別フォルダは import しない**：`entities/loan` から `entities/book` は使わない。だから貸出は `Book` 型を知らず、`bookId: string` だけを持つ。両方使う処理は上の層（features・widgets）に書く
2. **外からは `index.ts` 経由で使う**：`import { useBookStore } from "@/entities/book"`
3. **entities の UI は操作を持たない**：[AvailabilityChip](../src/entities/loan/ui/AvailabilityChip.tsx)・[LoanHistoryTable](../src/entities/loan/ui/LoanHistoryTable.tsx) は表示だけ。ボタンは features にある

## 2-5. なぜ MUI を使うのか

| 自分で CSS を書く（CSS Modules）                   | MUI                                                                   |
| -------------------------------------------------- | --------------------------------------------------------------------- |
| ボタン・入力欄・ダイアログを自分で作る             | 完成した部品がある（Dialog の Esc・フォーカスの閉じ込めまで入っている） |
| 色・余白は CSS 変数（tokens.css）                  | 色・余白は theme。`sx={{ p: 2, color: "text.secondary" }}`            |
| 見た目を細かく決められる                           | 決まった見た目（Material Design）。theme で色や角丸は変えられる       |
| 表のページ送り・日付の候補・評価の星は自分で作る   | `TablePagination`・`Autocomplete`・`Rating` がある                    |

試験で「UI ライブラリを使ってよい」なら、**画面を早く・アクセシブルに作れる** MUI が有利。自分で作る部分を「業務の処理（貸出・期限切れ）」に集中できる。
部品ごとの使い方は [MUI 部品カタログ](../../mui-catalog/)、画面の組み立て方は [MUI 画面構築ガイド](../../mui-catalog/docs/README.md) にまとめてある。

## 2-6. なぜ React Hook Form ＋ zod なのか

`useState` でフォームを書くと、入力欄ごとに state と onChange、送信時のチェック、エラーの state…と増えていく。

| 困りごと                           | React Hook Form ＋ zod では                                  |
| ---------------------------------- | ------------------------------------------------------------ |
| 入力欄ごとに state が要る          | `<FormTextField control={control} name="title" />` だけ       |
| チェックの if 文が散らばる         | zod のスキーマ 1 つにまとまる。エラー文もそこに書く          |
| 型とチェックが二重になる           | スキーマから型を作れる（`z.input`・`z.output`）              |
| 「今日以降」など、条件で変わるチェック | 今日の日付を受け取ってスキーマを作る関数（スキーマの工場） |

MUI の入力欄は、中の `<input>` を部品が持っているので、`register` ではなく **`Controller`（`useController`）でつなぐ**。毎回同じ書き方になるので、`FormTextField` にまとめている（[4-5](04-libraries.md#4-5-react-hook-form)）。

zod はフォーム以外でも使う。localStorage から読んだデータが正しい形かのチェックにも同じスキーマ（`bookSchema`・`loanSchema`）を使っている。
