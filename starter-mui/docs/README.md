# 試験の実装手順（雛形から提出まで）

> [雛形（starter-mui）](../README.md) ｜ 詳しい解説：[解説書（MUI 版・蔵書管理）](../../library/docs/README.md)・[MUI 画面構築ガイド](../../mui-catalog/docs/README.md)

MUI 版の雛形から始めて、**要件の書き出し → 実装 → 提出**までを、漏れなく進めるための手順書。
どのお題でも同じ順番で進められるように、ステップごとに「作るファイル」「やること」「終わりの確認」「コミット」をそろえてある。

## 全体の流れ（3 時間の例）

| 時間       | 章                                     | やること                                                     | 終わったら                         |
| ---------- | -------------------------------------- | ------------------------------------------------------------ | ---------------------------------- |
| 0:00〜0:10 | [1. 始める前に決める](01-plan.md)       | 要件をチェックリストに写す・画面／データ／操作を書き出す     | README に要件と設計メモがある      |
| 0:10〜0:20 | [2. 雛形で環境を作る](02-start.md)      | 雛形をコピー・4 か所を変える・起動・最初のコミット            | 「雛形が動いています」が出る       |
| 0:20〜2:10 | [3. 機能を作る](03-build.md)            | ステップ 1〜7：型と store → 一覧 → 追加 → 編集 → 削除 → 詳細 → お題の操作 | 必須の要件がすべて動く             |
| 2:10〜2:40 | [3. 機能を作る](03-build.md)            | ステップ 8〜9：絞り込み・並び替え・発展                       | 発展の要件ができたところまで       |
| 2:40〜3:00 | [4. 仕上げと提出](04-finish.md)         | 0 件・見つからない・スマホ幅 → 提出前チェック → README → push | チェックリストがすべて埋まる       |

**必須をすべて終えてから発展へ**。時間が足りなくなったら、ステップ 8 以降を削る。

## 1 枚のチェックリスト（印刷・手元に置く用）

```text
□ 0. 要件を README に写した（必須／発展を分けた）・画面とデータの型を書き出した
□ 1. 雛形をコピー → 4か所変更 → npm run dev で表示 → コミット「環境構築」
□ 2. entities：型（zod）・選択肢・store（persist）→ build が通る → コミット
□ 3. 一覧ページ：Route・メニュー・0件の EmptyState → コミット
□ 4. 追加：ボタン → ダイアログ（またはページ）→ エラー表示 → 再読み込みで残る → コミット
□ 5. 編集：同じフォームに今の値 → 保存で一覧に反映 → コミット
□ 6. 削除：確認ダイアログ → 通知 →（詳細からなら一覧へ戻る）→ コミット
□ 7. 詳細ページ：存在しない id で「見つかりません」→ コミット
□ 8. お題の操作（ステータス変更・在庫の増減・貸出 など）→ コミット
□ 9. 絞り込み・並び替え（URL に持つ）→ 0件の表示 → コミット
□ 10. 発展（一括操作・集計・ダッシュボード）→ コミット
□ 11. 0件・見つからない・入力エラー・スマホ幅（375px）・aria-label
□ 12. npm run build / npm run lint が通る・コンソールにエラーなし
□ 13. README（動かし方・できること・工夫した点・できなかった点）→ push
```
